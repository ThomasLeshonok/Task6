# Stored procedure reference

All fake data is generated by stored procedures in MySQL. The Streamlit application calls
`faker_list_locales`, `faker_generate_users` and `faker_generate_text` and only renders the result sets; the
benchmark and profiling tools call `faker_benchmark_users`, `faker_profile_users` and `faker_profile_primitives`.

The schema has been tested on MySQL 8.4.11 configured like a managed service (binary logging with GTID, `ANSI`
sql_mode, `sql_require_primary_key = ON`, an application user without `SUPER`, TLS), on MariaDB 10.4 (XAMPP) and on
Aiven's free hosted MySQL 8.4. The same arguments return identical results on all three.

Every routine is a `PROCEDURE`; there are no stored functions. With binary logging on and
`log_bin_trust_function_creators = 0`, MySQL refuses `CREATE FUNCTION` to users without `SUPER`, which is the usual
situation on hosted databases. Procedures are not subject to that restriction. Building blocks return their results
in `OUT` parameters; public procedures return one result set.

All tables, procedures and temporary tables are prefixed `faker_`, so the schema can share a database with other
applications.

## Installation

`python src/setup_db.py` runs `sql/schema/*.sql` in file name order, then the files of every
`sql/locales/<locale>/` folder. The scripts drop and recreate only `faker_` objects. They use `DELIMITER $$` around
procedure bodies, so they can also be imported one by one, in the same order, with the `mysql` client, phpMyAdmin
or MySQL Workbench. DDL is not transactional in MySQL; if an import stops partway, run it again from the start.

## Quick start

```sql
CALL faker_list_locales();                               -- en_US, de_DE

CALL faker_generate_users('en_US', 42, 0, 10, 2);        -- batch 0 (0-based positions 0-9), seed 42, up to 2 "about" sentences
CALL faker_generate_users('en_US', 42, 1, 10, 2);        -- batch 1 (0-based positions 10-19)
CALL faker_generate_users('de_DE', 42, 0, 10, 2);        -- same seed, German data
CALL faker_generate_user('en_US', 42, 14, 2);            -- only the user at 0-based position 14

CALL faker_generate_text('de_DE', 7, 3, 4);              -- 3 paragraphs of 4 sentences

-- Building blocks write OUT parameters; read them through session variables.
CALL faker_rng_key('en_US', 42, 0, @key);
CALL faker_random_normal(@key, 'my.height', 170, 8, @height);
CALL faker_random_location(@key, 'geo', 'de_DE', @lat, @lon);      -- inside Germany
CALL faker_fill_digits(@key, 'phone', '+1 (###) %##-####', @phone);
CALL faker_random_value(@key, 'surname', 'de_DE', 'last_name', '', @surname);
SELECT @height, @lat, @lon, @phone, @surname;
```

## Conventions

- Prefixes: `p_` for parameters, `v_` for local variables, `c_` for named constants.
- Common parameters, used with the same meaning everywhere:

  | Parameter | Type | Meaning |
  |-----------|------|---------|
  | `p_locale` | `VARCHAR(16)` | Locale code, a row of `faker_locales` (`en_US`, `de_DE`) |
  | `p_seed` | `BIGINT` | User-supplied seed |
  | `p_key` | `CHAR(32)` (ascii) | Key of one generated record, from `faker_rng_key` |
  | `p_stream` | `VARCHAR(255)` | Label of one random draw of that record (`'name.first'`, `'body.height'`); different labels give independent values |
  | `p_category`, `p_variant` | `VARCHAR(64)`, `VARCHAR(255)` | Identify a lookup list; `p_variant` is `''` for a list that is not split (see [Lookup lists](#lookup-lists-and-weighted-choice)) |

- Text parameters are declared `CHARACTER SET utf8mb4` and all tables use the `utf8mb4_bin` collation. Non-Latin-1
  letters survive in a database whose default character set is `latin1`, and comparisons are exact (`Die`/`die`,
  `schon`/`schön` are different values).
- Every script starts with
  `SET SESSION sql_mode = 'STRICT_ALL_TABLES,ERROR_FOR_DIVISION_BY_ZERO,NO_ENGINE_SUBSTITUTION'`. A routine keeps the
  sql_mode it was created with, so the procedures behave the same on servers with different defaults (for example
  `ANSI` mode, in which `"` quotes identifiers).
- Invalid arguments raise `SIGNAL SQLSTATE '22023'` (invalid parameter value) with a descriptive message. Clients
  receive error 1644 with that SQLSTATE.
- Every table, including temporary tables, has a primary key, as required by `sql_require_primary_key`.
- Procedures that return a result set build it in a session temporary table (`faker_batch`, `faker_text`,
  `faker_sample`, `faker_profile`) and drop it afterwards. Concurrent sessions never see each other's rows. A
  caller's own temporary table with one of these names is replaced.

## Call structure

`faker_generate_users` calls `faker_add_user_to_batch` once per user. The tree shows the procedures each step uses:

```
faker_generate_users / faker_generate_user                     09_api
├── faker_assert_locale, faker_open_batch                      09_api
└── faker_add_user_to_batch                                    09_api
    ├── faker_rng_key                                          02_random
    ├── faker_random_gender                                    05_person
    ├── faker_random_person_name                               05_person
    ├── faker_random_address                                   06_address
    │   ├── faker_random_street
    │   └── faker_random_postal_code
    ├── faker_random_location                                  06_address
    │   ├── faker_random_spherical_box                         02_random
    │   └── faker_border_contains                              06_address
    ├── faker_random_physical                                  07_physical
    │   ├── faker_random_measure ── faker_random_normal_bounded  02_random
    │   └── faker_format_height, faker_format_weight
    ├── faker_random_phone                                     05_person
    ├── faker_random_email ── faker_to_ascii                   05_person, 04_text
    ├── faker_random_int (number of "about" sentences)         02_random
    └── faker_markov_text ── faker_markov_sentence             08_markov

Shared by the steps above:
    faker_expand, faker_render, faker_fill_digits              04_text     templates and digit masks
    faker_random_value, faker_random_item, faker_pick          03_lookup   weighted choice from lookup lists
    faker_random_uniform, faker_random_normal                  02_random   counter-based random numbers
```

Each file calls only procedures of the same or earlier files. Locale differences are data (lists, templates,
distribution parameters, border polygons); the procedures are the same for every locale.

## Public API

### faker_list_locales

```sql
faker_list_locales()
```

Result set `code, name`: the supported locales, ordered by `faker_locales.sort_order`, then `name`.

### faker_assert_locale

```sql
faker_assert_locale(IN p_locale VARCHAR(16))
```

Returns nothing for a known locale. For an unknown one it raises SQLSTATE 22023 with the message
`Unknown locale "xx". Available: de_DE, en_US`. Called first by every public generator.

### faker_generate_users

```sql
faker_generate_users(IN p_locale VARCHAR(16), IN p_seed BIGINT, IN p_batch INT, IN p_batch_size INT,
                     IN p_about_sentences INT)
```

Returns one batch of users as a result set, ordered by `position`.

| Argument | Description |
|----------|-------------|
| `p_locale` | Locale of the generated data |
| `p_seed` | Seed; any `BIGINT` |
| `p_batch` | 0-based batch index; must be `>= 0` |
| `p_batch_size` | Users per batch; must be `>= 1` |
| `p_about_sentences` | Maximum number of sentences in `about`. The actual count is drawn uniformly from `1 .. GREATEST(p_about_sentences, 1)` per user |

The batch holds the 0-based positions `p_batch * p_batch_size` to `(p_batch + 1) * p_batch_size - 1`. A user depends
only on locale, seed and position, so the same position yields the same user for any batch size. Errors: unknown
locale (see `faker_assert_locale`); `Batch index must be >= 0 and batch size >= 1`.

Result columns (examples: en_US and de_DE, seed 42, position 15):

| Column | Type | Content | Example en_US / de_DE |
|--------|------|---------|-----------------------|
| `position` | `BIGINT` | 1-based position: 0-based position + 1 | `15` / `15` |
| `full_name` | `VARCHAR(255)` | Rendered name template | `Dr. Otis McKinney` / `Frau Sandra Salomon` |
| `gender` | `VARCHAR(255)` | Localized gender label | `Male` / `weiblich` |
| `address` | `VARCHAR(500)` | Rendered address template | `7 Pelican Street Apt. 33, Santa Monica, CA 90483` / `Stuttgarter Str. 46, 10416 Berlin, Deutschland` |
| `latitude`, `longitude` | `DOUBLE` | Degrees, 6 decimals, inside the country | `33.634014, -111.306436` / `53.724219, 13.133485` |
| `height` | `VARCHAR(64)` | Height in the locale's format | `6 ft 2 in` / `163 cm` |
| `height_cm` | `DOUBLE` | Height in cm, 1 decimal | `187` / `163.1` |
| `weight` | `VARCHAR(64)` | Weight in the locale's format | `185 lb` / `71,9 kg` |
| `weight_kg` | `DOUBLE` | Weight in kg, 1 decimal | `84.1` / `71.9` |
| `eye_color`, `hair_color`, `blood_type` | `VARCHAR(255)` | Localized words | `Hazel, Red, B-` / `blaugrau, schwarz, A+` |
| `phone` | `VARCHAR(255)` | Rendered phone template | `(818) 646-2173` / `+49 173 1969 4364` |
| `email` | `VARCHAR(255)` | ASCII e-mail address | `o.mckinney@comcast.net` / `ssalomon@gmail.com` |
| `about` | `TEXT` | Markov chain sentences | |

```sql
-- The user at 0-based position 14 appears in all three results:
CALL faker_generate_users('en_US', 42, 1, 10, 2);   -- 5th row
CALL faker_generate_users('en_US', 42, 0, 20, 2);   -- 15th row
CALL faker_generate_user('en_US', 42, 14, 2);       -- the only row
```

### faker_generate_user

```sql
faker_generate_user(IN p_locale VARCHAR(16), IN p_seed BIGINT, IN p_position BIGINT, IN p_about_sentences INT)
```

Returns the single user at 0-based position `p_position` of the `(p_locale, p_seed)` sequence, with the same columns
as `faker_generate_users`. Only the locale is validated.

### faker_generate_text

```sql
faker_generate_text(IN p_locale VARCHAR(16), IN p_seed BIGINT, IN p_paragraphs INT, IN p_sentences INT)
```

Result set `paragraph_no INT, paragraph TEXT`: `p_paragraphs` paragraphs of exactly `p_sentences` Markov chain
sentences each, reproducible for `(p_locale, p_seed)`. The key is `faker_rng_key(p_locale, p_seed, 0)`; paragraph
*n* uses the stream `text.p<n>`. Counts are not validated: `p_paragraphs <= 0` returns no rows and
`p_sentences <= 0` returns empty paragraphs. Raises `No Markov model for this locale; run faker_train_markov first`
when the locale has no trained chain.

### Batch helpers

| Procedure | Description |
|-----------|-------------|
| `faker_open_batch()` | Creates (or recreates) the temporary table `faker_batch` with the result columns above |
| `faker_add_user_to_batch(IN p_locale VARCHAR(16), IN p_seed BIGINT, IN p_position BIGINT, IN p_about_sentences INT)` | Generates the user at 0-based `p_position` and inserts it into `faker_batch`. Does not validate the locale |

## Tables

| Table | Content |
|-------|---------|
| `faker_locales` | One row per locale: `code` (`en_US`), `name`, `language_code`, `country_code`, `decimal_separator`, `sort_order` |
| `faker_lookup_lists` | Catalog of weighted lists, unique on `(locale, category, variant)`, with `item_count` and `total_weight` |
| `faker_lookup_values` | Items of all lists: `item_no`, `value`, `weight` (`> 0`), running `cum_weight`, optional `details` JSON. Index `faker_lookup_values_pick (list_id, cum_weight)` |
| `faker_distributions` | Normal distribution parameters per `(locale, attribute, variant)`: `mean`, `stddev`, `min_value`, `max_value` |
| `faker_markov_corpus` | Source texts per locale: `title`, `body` |
| `faker_markov_models` | Trained chain per locale: `chain_order`, `max_words`, `token_count`, `state_count`, `trained_at` |
| `faker_geo_regions` | Parts of a locale's territory: `name`, bounding box `lat_min`, `lat_max`, `lon_min`, `lon_max`, `tile_grid`, `border` (GEOMETRY multipolygon in lon/lat degrees) |
| `faker_geo_tiles` | Precomputed border test: one row per tile `(row_no, col_no)` of a region's box, with `inside` and, for tiles the border crosses, the clipped `border` |

There are no per-language tables. First names of both locales, German street types and US area codes are rows of
`faker_lookup_values`, distinguished by the list's `locale`, `category` and `variant` (`first_name`/`male`,
`first_name`/`female`, `last_name`/`''`). The Markov chain is stored in the same tables (`category = 'markov'`,
`variant` = chain state).

## Random numbers

### Algorithm

The generator is counter-based: a random value is a hash of what is being generated, not the next element of a
sequence. No state is kept between calls, so the result does not depend on call order, any position can be
generated directly, and every session computes the same values.

```
key  = MD5(CONCAT_WS(':', locale, seed, position))               32 hex digits, one per generated record
bits = CONV(LEFT(MD5(CONCAT(key, ':', stream)), 16), 16, 10)     64 bits, one per draw
u    = (bits >> 11) / 2^53                                       uniform DOUBLE in [0, 1)
```

- `position` is `batch_index * batch_size + index_in_batch` (0-based), so a record depends on locale, seed and
  position only.
- Each attribute draws from its own stream label. Draws are independent, and adding an attribute does not change
  the values of existing ones. Sub-draws append a suffix to the stream (`#1`, `#2`, `#lat`, `.1`, `.2`, ...); the
  complete list is in [Stream labels](#stream-labels).
- The uniform keeps the top 53 bits, the size of the DOUBLE mantissa, so every value is exactly representable and
  the values are evenly spaced with step 2^-53.
- MD5 is used as a fast, well-mixed hash that is built in and identical on every MySQL and MariaDB server. It has no
  security role here.
- A `CALL` costs about as much as the hash. `faker_random_value`, `faker_random_item`, `faker_fill_digits` and the word
  loop of `faker_markov_sentence` therefore compute the uniform inline instead of calling `faker_random_uniform`.
  `tests/test_procedures.py` checks that they produce the same numbers.

### Normal distribution: Box-Muller transform

`faker_random_normal` draws two independent uniforms, `u1` from `<stream>#1` and `u2` from `<stream>#2`, and returns

```
z = sqrt(-2 ln(1 - u1)) * cos(2 pi u2)          x = mean + stddev * z
```

`1 - u1` lies in [0, 1], so the logarithm is always defined. The pair `(sqrt(-2 ln(1 - u1)), 2 pi u2)` is the polar
form of a two-dimensional standard normal vector: the radius has the Rayleigh distribution and the angle is uniform.
Its projection on one axis is N(0, 1). Only the cosine component is used; the second, independent sine component is
discarded, so each normal value costs two hashes.

### Uniform points on the sphere

Choosing latitude and longitude as two independent uniform numbers concentrates points near the poles, because a
band of latitude near a pole has a much smaller area than a band of the same height at the equator. For a constant
density per unit area inside the box `lat_min..lat_max`, `lon_min..lon_max`:

- the longitude is uniform: `lambda = lon_min + u (lon_max - lon_min)`, with `u` from `<stream>#lon`;
- the area element of the sphere is `cos(phi) dphi dlambda`, so the area between `lat_min` and `phi` is
  proportional to `sin(phi) - sin(lat_min)`. Inverting this CDF gives, with `u` from `<stream>#lat`,

  ```
  phi = asin(sin(lat_min) + u * (sin(lat_max) - sin(lat_min)))
  ```

  Equivalently, `sin(phi)` is uniform between `sin(lat_min)` and `sin(lat_max)` (Archimedes' hat-box theorem).

For the whole sphere (`faker_random_geolocation`) this reduces to `phi = asin(2u - 1)`. Half of the sphere's area lies
between 30° S and 30° N (`sin 30° = 0.5`); `test_geolocation_is_uniform_on_the_sphere` samples 10,000 points with
`faker_sample_geolocations` and checks that about 50% fall in that band (uniform latitudes would give 33%), and that
`sin(phi)` has mean 0 and variance 1/3.

## Lookup lists and weighted choice

A lookup list is identified by `(locale, category, variant)`. `variant` splits one category, for example
`first_name`/`male` and `first_name`/`female`; it is `''` for a list that is not split. Each item has a positive
`weight`; the probability of an item is its weight divided by the list's total weight. Templates, word lists, compound
items such as cities, border regions and Markov transitions are all lookup lists.

### Weighted choice by inverse CDF

Each item stores `cum_weight`, the running sum of weights in item order, and the list stores `total_weight`. For a
uniform `u` in [0, 1] the chosen item is the first one with `cum_weight >= u * total_weight`. An item with weight `w`
covers an interval of length `w` of `[0, total_weight)`, so it is chosen with probability `w / total_weight`.

The list is found through its unique key, and the item through a single range seek on the index
`(list_id, cum_weight)`, which is O(log n) in the list size. The query specifies
`FORCE INDEX (faker_lookup_values_pick)`: without the hint the optimizer may read the list from its first item
(`ref` access on `list_id`) when it expects the match far down the list, which costs one step per skipped item.
`faker_random_location` and `faker_markov_sentence` contain the same query, joined to the data they need next.

### Choosing values

| Procedure | Description |
|-----------|-------------|
| `faker_pick(IN p_locale, IN p_category, IN p_variant, IN p_u DOUBLE, OUT p_value VARCHAR(255), OUT p_details MEDIUMTEXT)` | Item covering the uniform `p_u` (in [0, 1)) and its `details` JSON. Both are NULL when the list does not exist |
| `faker_random_value(IN p_key, IN p_stream, IN p_locale, IN p_category, IN p_variant, OUT p_value VARCHAR(255))` | `faker_pick` with the uniform of `(p_key, p_stream)` |
| `faker_random_item(IN p_key, IN p_stream, IN p_locale, IN p_category, IN p_variant, OUT p_value VARCHAR(255), OUT p_details MEDIUMTEXT)` | The same, also returning `details` (used for cities) |
| `faker_list_categories(IN p_locale)` | Result set `category, variant, item_count, total_weight` of all lists of the locale except Markov states |

### Loading lists

The loaders below create the list when it does not exist and recompute running weights and totals when they finish.
The locale must already exist in `faker_locales`.

| Procedure | Description |
|-----------|-------------|
| `faker_add_words(IN p_locale, IN p_category, IN p_variant, IN p_words MEDIUMTEXT, IN p_delimiter VARCHAR(8))` | Appends delimited words with weight 1, for example `'James\|John\|Robert'` with `'\|'`. Line breaks, tabs and repeated spaces are normalized and each word is trimmed, so a list may span many lines. Empty words and words already in the list are skipped |
| `faker_add_values(IN p_locale, IN p_category, IN p_variant, IN p_values MEDIUMTEXT, IN p_weights MEDIUMTEXT)` | Appends the strings of the JSON array `p_values`. `p_weights` is a JSON array of numbers in the same order, or NULL for weight 1; a missing entry also means weight 1. Values already in the list are skipped |
| `faker_add_items(IN p_locale, IN p_category, IN p_variant, IN p_fields MEDIUMTEXT, IN p_items MEDIUMTEXT)` | Appends compound items. `p_items` is a JSON array of arrays and `p_fields` a JSON array naming the positions. `value` is required (otherwise SQLSTATE 22023 `faker_add_items: p_fields must contain "value"`), `weight` is optional, every other field is stored in `details` as a string. Items are not de-duplicated, because two cities may share a name |
| `faker_ensure_list(IN p_locale, IN p_category, IN p_variant, OUT p_list_id INT)` | Id of the list, created empty when missing |
| `faker_append_value(IN p_list_id INT, IN p_value VARCHAR(255), IN p_weight DOUBLE, IN p_details MEDIUMTEXT, IN p_unique BOOLEAN)` | Appends one item at the end of the list. An empty value is ignored; with `p_unique`, so is a value already in the list. Does not update `cum_weight`: call `faker_refresh_lists` afterwards |
| `faker_refresh_lists(IN p_locale, IN p_category)` | Recomputes `cum_weight`, `item_count` and `total_weight` of all lists of the category |
| `faker_clean_text(IN p_text MEDIUMTEXT, OUT p_result MEDIUMTEXT)` | Replaces line breaks and tabs with spaces, collapses runs of spaces and trims both ends |

```sql
CALL faker_add_values('en_US', 'title', 'female', '["Ms.", "Mrs.", "Miss", "Dr."]', '[40, 34, 10, 12]');
CALL faker_add_words('en_US', 'last_name', '', 'Smith|Johnson|Williams', '|');
CALL faker_add_items('en_US', 'city', '', '["value", "region_code", "postal_prefix"]',
                     '[["Boston", "MA", "021"], ["Denver", "CO", "802"]]');
```

Because `faker_add_words` and `faker_add_values` skip existing values, a locale script can be run again without
duplicating words. To remove items, delete them from `faker_lookup_values` and call `faker_refresh_lists`.

## Templates and formatting

Formats such as names, addresses and phone numbers are weighted lists of templates. A template combines literal
text, `{placeholder}` names and digit masks:

| Syntax | Meaning | Example |
|--------|---------|---------|
| `{name}` | Value of the variable `name` | `{street_name} {street_type}` |
| `#` | Random digit 0-9 | `#####` gives `02139` |
| `%` | Random digit 1-9 (no leading zero) | `(%##) %##-####` |
| any other character | Copied unchanged | `+49 (0)`, `Apt.`, `ft` |

There is no escape sequence: a template cannot contain a literal `#` or `%`.

| Procedure | Description |
|-----------|-------------|
| `faker_fill_digits(IN p_key, IN p_stream, IN p_template VARCHAR(255), OUT p_result VARCHAR(255))` | Replaces each `#` and `%` with a digit; other characters are kept. The character at 1-based position *i* uses the stream `<p_stream>.<i>` and equals `faker_random_int(p_key, '<p_stream>.<i>', min, 9)` with `min` 0 or 1 |
| `faker_render(IN p_template VARCHAR(255), IN p_vars MEDIUMTEXT, OUT p_result MEDIUMTEXT)` | `p_vars` is a JSON object (or NULL). Replaces each `{name}` with the value of key `name`; null values give an empty string. Placeholders without a key are removed. Whitespace is then normalized as in `faker_clean_text`, which removes the double spaces left by empty parts |
| `faker_expand(IN p_key, IN p_stream, IN p_locale, IN p_template VARCHAR(255), IN p_vars MEDIUMTEXT, OUT p_result MEDIUMTEXT)` | Like `faker_render`, but each placeholder that is not a key of `p_vars` (which may be NULL) is drawn with `faker_random_value(p_key, '<p_stream>.<name>', p_locale, '<name>', '')`, that is, from the list named like the placeholder. ### faker_random_person_name

```sql
faker_random_person_name(IN p_key, IN p_locale, IN p_gender VARCHAR(255),
                         OUT p_title, OUT p_first_name, OUT p_middle_name, OUT p_last_name, OUT p_suffix,
                         OUT p_full_name)                                    -- all VARCHAR(255)
```

Builds a full name from a weighted template of the list `name_format`. The weight of a template is the share of
people whose names have that form.

1. Draw the template (stream `name.format`).
2. Draw the first name (`first_name`, variant `p_gender`) and the last name (`last_name`). These are always drawn.
3. Draw only the parts that the template contains:

   | Placeholder | Source | Stream |
   |-------------|--------|--------|
   | `{title}` | `title`, variant `p_gender` | `name.title` |

   | `{last2}` | `last_name`, an independent second surname for double names | `name.last2` |
   | `{particle}` | `name_particle` (`von`, `von der`, `zu`, `van`, ...) | `name.particle` |
   | `{suffix}` | `suffix` | `name.suffix` |

4. Render the template with `faker_render`.

Templates shipped with the locales:

| en_US template | Weight | de_DE template | Weight |
|----------------|-------:|----------------|-------:|
| `{first} {last}` | 44 | `{first} {last}` | 54 |
| `{first} {middle_initial}. {last}` | 18 | `{first} {middle} {last}` | 12 |
| `{first} {middle} {last}` | 12 | `{first}-{middle} {last}` | 6 |
| `{title} {first} {last}` | 10 | `{title} {first} {last}` | 12 |
| `{title} {first} {middle_initial}. {last}` | 4 | `{title} {first} {middle} {last}` | 3 |
| `{first} {last} {suffix}` | 5 | `{first} {last}-{last2}` | 8 |
| `{first} {middle_initial}. {last} {suffix}` | 3 | `{first} {particle} {last}` | 4 |
| `{first} {last}-{last2}` | 4 | `{title} {first} {particle} {last}` | 1 |

**Customizing names.** Name generation is controlled by data only:

- To change how often a form occurs, change the template's weight.
- To add a form that uses the existing placeholders, such as `{last}, {first}`, add a template:
  `CALL faker_add_values('en_US', 'name_format', '', '["{last}, {first}"]', '[5]');`
- To change titles, suffixes, particles or the frequency of individual names, edit the corresponding lists; a name's
  weight is its relative frequency.
- The placeholder set is fixed in the procedure. A placeholder outside the table above is removed when the name is
  rendered; supporting a new one requires a change to `faker_random_person_name`.

## Location inside the country

Coordinates lie inside the locale's country and have a constant density per unit area, so their distribution follows
land area. The method combines the equal-area box sampling of `faker_random_spherical_box` with rejection sampling
against real border polygons.

### Rejection sampling

The territory of a locale consists of one or more regions (`faker_geo_regions`), each with a border multipolygon
and its bounding box. The list `geo_region` holds the regions, each weighted by the spherical area of its box,
`(sin lat_max - sin lat_min) * (lon_max - lon_min in radians)`. Attempt *n* (n = 1, 2, ...):

1. choose a region from `geo_region` (stream `<p_stream>.<n>.region`);
2. draw an equal-area point in its box with `faker_random_spherical_box` (stream `<p_stream>.<n>`);
3. accept the point when the region's border contains it (`faker_border_contains`); otherwise start attempt *n + 1*.

Choosing the region again in every attempt makes the result uniform over all regions together. In one attempt, a
point falls into a small area `dA` of region *r* with probability
`(box_area_r / total_box_area) * (dA / box_area_r) = dA / total_box_area`, which is the same everywhere. Accepted
points are therefore uniform over the union of the territories.

Measured acceptance (5,000 attempts each): 64% for de_DE and 47% for en_US, so a location takes on average 1.6 and
2.2 attempts. After 64 rejected attempts (probability below 10^-17) the last point is returned; it lies inside the box
but may lie outside the border. Coordinates are rounded to 6 decimals (about 0.1 m), which also removes last-digit
differences of `SIN` and `ASIN` between MySQL and MariaDB.

### Regions

Borders come from Natural Earth admin-0 countries (1:50m, v5.1.2, public domain) and are written to
`sql/locales/<locale>/05_geo.sql` by `tools/build_regions.py`. The tool assigns each polygon part to a region by the
position of its centre; the box of a region is the exact envelope of its parts, computed in SQL.

| Locale | Region | Box (lat; lon) | Parts | Share of box area | Share of points |
|--------|--------|----------------|------:|------------------:|----------------:|
| de_DE | Germany | 47.28..55.06; 5.86..15.02 | 6 | 100% | 100% |
| en_US | Contiguous United States | 24.54..49.37; -124.71..-66.99 | 52 | 70.4% | about 84% |
| en_US | Alaska | 51.60..71.41; -178.19..-130.01 | 62 | 28.1% | about 16% |
| en_US | Alaska, Aleutian Islands west of 180 | 51.37..53.01; 172.49..179.78 | 6 | 0.5% | below 0.1% |
| en_US | Hawaii | 18.96..22.22; -160.24..-154.80 | 7 | 1.0% | about 0.2% |

The share of points was measured on 5,000 en_US locations and matches the regions' shares of the US land area. The Aleutian Islands cross the 180° meridian, so the
islands east of 172° E form a separate region; a single box would otherwise span the whole globe. Alaska's box is
mostly sea and is accepted less often than the contiguous states, so the share of points follows land area.
`test_us_locations_follow_area` checks these shares; `test_locations_lie_inside_the_country_border` checks sampled
points against the borders with an independent ray-casting point-in-polygon test.

### Border tiles

`ST_Contains` on a complete border scans thousands of vertices: on MariaDB 10.4 it takes about 3.6 ms per point for
Alaska and 0.26 ms for Germany. `faker_add_geo_region` therefore precomputes the test in `faker_geo_tiles`. The box is
divided into 64 x 64 tiles; each tile is wholly inside the border, wholly outside it, or crossed by it, in which case
it stores only the part of the border that overlaps the tile (5 to 13 vertices on average, depending on the region).
A border test is then one primary key lookup (row and column computed from the point and the box), plus
`ST_Contains` on the small clipped border for the 3-13% of tiles the border crosses. This takes about 0.11 ms
regardless of the size of the border.

`faker_build_geo_tiles` works top-down like a quadtree. It starts with the whole box and the whole border. A square
that the border crosses is divided into four quarters; each quarter keeps `ST_Intersection` of its parent's border
part with itself, so the geometry becomes smaller at every level. A quarter whose part has no area is outside, a
quarter contained in its part (`ST_Contains(part, quarter)`) is inside, and both are written out tile by tile.
Each quarter is evaluated with a margin of 0.000001° around it, much wider than the rounding error of the tile index.
Every point mapped to a tile therefore lies inside the square the tile was evaluated with, and the tiles give the
same answer as `ST_Contains` on the whole border; `test_border_tiles_answer_like_the_whole_border` compares both on
random points. Building the tiles for the five shipped regions takes about 5 s during installation.

For more precise borders, regenerate the files from the 1:10m data:
`python tools/build_regions.py ne_10m_admin_0_countries.geojson`. Germany then has 3,027 vertices instead of 562 and
the USA 35,981 instead of 5,753. Building the tiles takes longer; generating points does not.

## Physical attributes

### Method

- Height is normally distributed per locale and gender: en_US men 175.4 ± 7.6 cm, women 161.7 ± 7.1 cm; de_DE men
  179.0 ± 7.2 cm, women 165.8 ± 6.6 cm.
- Weight is not drawn directly. The body mass index is drawn from a normal distribution and
  `weight = BMI * (height in m)^2`, so taller people are heavier on average, as in real data.
- Eye color, hair color and blood type are weighted lists with locale-specific frequencies and localized words, for
  example blue eyes with weight 27 of 104 in en_US and 38 of 100 in de_DE, blood type O+ 37.4% in en_US.
- Values are stored in metric units. Format templates decide what is shown: `5'10"` or `176 lbs` in en_US, `1,78 m`
  or `82,4 kg` in de_DE.

Normal values are clamped to `[min_value, max_value]` of `faker_distributions`:

| Locale | Attribute | Variant | Mean | SD | Min | Max | Min (SD from mean) | Max (SD from mean) |
|--------|-----------|---------|-----:|---:|----:|----:|-------------------:|-------------------:|
| en_US | `height_cm` | male | 175.4 | 7.6 | 137 | 214 | -5.1 | +5.1 |
| en_US | `height_cm` | female | 161.7 | 7.1 | 126 | 198 | -5.0 | +5.1 |
| en_US | `bmi` | male | 29.1 | 5.4 | 16 | 52 | -2.4 | +4.2 |
| en_US | `bmi` | female | 29.6 | 6.9 | 16 | 58 | -2.0 | +4.1 |
| de_DE | `height_cm` | male | 179.0 | 7.2 | 143 | 215 | -5.0 | +5.0 |
| de_DE | `height_cm` | female | 165.8 | 6.6 | 133 | 199 | -5.0 | +5.0 |
| de_DE | `bmi` | male | 26.8 | 4.4 | 16 | 48 | -2.5 | +4.8 |
| de_DE | `bmi` | female | 25.3 | 5.2 | 15 | 51 | -2.0 | +4.9 |

The height bounds lie about 5 standard deviations from the mean, so fewer than one height in a million is clamped.
The BMI lower bounds lie 2.0-2.5 standard deviations below the mean: 0.7% (men) to 2.4% (women) of BMI draws are
set to the lower bound. To reduce this, lower `min_value` in the locale's `03_contact.sql`.

## Markov chain text

A word-level Markov chain of order *k* generates text in the locale's language: the next word is drawn with the
frequency with which it followed the previous *k* words in the corpus. The shipped corpora are original texts written
for this project; Lorem ipsum is not used.

### Training

`CALL faker_train_markov('de_DE', 1, 30)`:

1. Read the corpus texts of the locale in `corpus_id` order and normalize whitespace with `faker_clean_text`.
2. Split each text at spaces into tokens. Punctuation stays attached to the word (`Haus,`, `Nacht.`), so the chain
   also learns where commas and sentence ends occur.
3. Keep the current state, the last *k* tokens joined by spaces. Each text and each sentence starts in the start
   state of *k* markers `^` (`^ ^` for order 2). Record every `(state, next token)` pair. After a sentence-ending
   token the state returns to the start state.
4. Count the pairs and store them as lookup lists: category `markov`, variant = state, value = next token,
   weight = count. Record the model in `faker_markov_models`.

A token ends a sentence when it ends with `.`, `!` or `?`, optionally followed by closing quotes or a bracket
(regular expression `[.!?]['"»«“”„)]*$`).

### Generation

`faker_markov_sentence` starts in the start state. For word *i* it draws the next token from the state's list with
the uniform of stream `<p_stream>.<i>`, appends it and shifts the state. It stops at a sentence-ending token, at a
state without successors, or after the model's `max_words` tokens. `faker_finish_sentence` then capitalizes the first
letter, removes trailing `,`, `;`, `:` and `-`, and appends a period when the sentence does not end with `.`, `!` or
`?`.

The word loop computes the uniform, the weighted choice, the sentence-end test and the next state inline instead of
calling `faker_random_value`, `faker_is_sentence_end` and `faker_markov_next_state`, which saves five nested `CALL`s
per word. `test_markov_sentence_walks_the_chain_with_random_value` compares it with a walk built from those
procedures.

Order 1 gives the most varied text from the small shipped corpora. Orders 2 and 3 read more fluently but need a larger
corpus to avoid reproducing it verbatim. To extend a corpus, insert texts with
`INSERT INTO faker_markov_corpus (locale, title, body)` and run `faker_train_markov` again.

| Procedure | Description |

| `faker_markov_text(IN p_key, IN p_stream, IN p_locale, IN p_sentences INT, OUT p_text TEXT)` | `p_sentences` sentences joined by spaces; sentence *n* uses the stream `<p_stream>.s<n>`. Empty for `p_sentences <= 0` |

Calls each building block `p_count` times with typical arguments and returns
`primitive, calls, seconds, us_per_call, us_over_loop`, where `us_over_loop` is the cost per call minus the cost of
the empty loop. Measured primitives: the baselines `empty_loop` (loop only), `call_overhead` (an empty `CALL`) and
`select_into` (a primary key `SELECT ... INTO`); the random number procedures; `faker_pick`, `faker_random_value`,
`faker_random_item` and `faker_random_value(markov)` (a pick on a Markov state); `faker_fill_digits(#####)`,
`faker_render`, `faker_expand`, `faker_to_ascii`, `faker_format_decimal`; `faker_random_spherical_box`;
`ST_Contains(biggest border)` and `faker_border_contains(biggest border)` on the locale's largest region (Alaska for
en_US); `faker_random_location`; and `faker_markov_sentence`.

```sql
CALL faker_profile_users('en_US', 42, 0, 1000, 2);
CALL faker_profile_primitives('de_DE', 500);
```

### Helpers

| Procedure | Description |
|-----------|-------------|
| `faker_profile_primitive(IN p_locale, IN p_primitive VARCHAR(64), IN p_count INT, OUT p_seconds DOUBLE)` | Runs one primitive of the list above `p_count` times and returns the elapsed time. An unknown name raises error 1339 (`Case not found for CASE statement`) |
| `faker_profile_lap(INOUT p_mark DATETIME(6), INOUT p_microseconds BIGINT)` | Adds the microseconds since `p_mark` to `p_microseconds` and sets `p_mark` to the current time |
| `faker_profile_noop()` | Empty procedure; its cost is the cost of one `CALL` |
| `faker_open_profile()` | Creates the temporary result table `faker_profile` |

## Stream labels

Streams used for one user; `<i>` is the 1-based character position in a digit mask, `<n>` an attempt or sentence
number, `<placeholder>` a template placeholder drawn from a list.

| Attribute | Streams |
|-----------|---------|
| Gender | `person.gender` |
| Name | `name.format`, `name.first`, `name.last`, `name.title`, `name.middle`, `name.middle#retry`, `name.last2`, `name.particle`, `name.suffix` |
| Address | `address.format`, `address.city`, `address.postal_code`, `address.postal_code.digits.<i>`, `street.format`, `street.<placeholder>`, `address.building`, `address.building.digits.<i>`, `address.secondary`, `address.secondary.digits.<i>` |
| Location | `geo.<n>.region`, `geo.<n>#lat`, `geo.<n>#lon`; `geo#lat`, `geo#lon` for a locale without regions |
| Body | `body.height#1`, `body.height#2`, `body.bmi#1`, `body.bmi#2`, `body.height.format`, `body.weight.format`, `body.eye_color`, `body.hair_color`, `body.blood_type` |
| Phone | `phone.format`, `phone.<placeholder>`, `phone.digits.<i>` |
| E-mail | `email.format`, `email.digits.<i>`, `email.domain` |
| About | `about.sentences`, `about.s<n>.<i>` (word *i* of sentence *n*) |

`faker_generate_text` uses the key of position 0 and the streams `text.p<p>.s<n>.<i>`. When writing a new
procedure, use stream labels that do not begin with any of the prefixes above, so its draws stay independent of the
existing attributes.

## Adding a locale

Example: French (France). No changes to tables or procedures are needed.

1. Create `sql/locales/fr_FR/01_locale.sql`:

   ```sql
   SET NAMES utf8mb4;
   INSERT INTO faker_locales (code, name, language_code, country_code, decimal_separator, sort_order)
   VALUES ('fr_FR', 'Français (France)', 'fr', 'FR', ',', 3);
   CALL faker_add_items('fr_FR', 'gender', '', '["value", "weight", "label"]',
                        '[["male", 49, "homme"], ["female", 51, "femme"]]');
   CALL faker_add_values('fr_FR', 'name_format', '', '["{first} {last}", "{title} {first} {last}"]', '[85, 15]');
   CALL faker_add_words('fr_FR', 'first_name', 'male', 'Jean|Pierre|Louis', '|');
   ```

2. Add the other lists of the [catalog](#list-catalog) that the templates use (names, addresses, phones, e-mails,
   body formats and traits) and the rows of `faker_distributions`:

   ```sql
   INSERT INTO faker_distributions (locale, attribute, variant, mean, stddev, min_value, max_value) VALUES
       ('fr_FR', 'height_cm', 'male',   <mean>, <stddev>, <min>, <max>),
       ('fr_FR', 'height_cm', 'female', <mean>, <stddev>, <min>, <max>),
       ('fr_FR', 'bmi',       'male',   <mean>, <stddev>, <min>, <max>),
       ('fr_FR', 'bmi',       'female', <mean>, <stddev>, <min>, <max>);
   ```

3. Add corpus texts to `faker_markov_corpus` and train the chain: `CALL faker_train_markov('fr_FR', 1, 30);`.
4. For coordinates, add an entry to `COUNTRIES` in `tools/build_regions.py`, for example
   `"fr_FR": ("France", {"Metropolitan France": (41.0, 51.5, -5.5, 10.0), ...})`, where each box selects the polygon
   parts whose centre lies inside it (`None` takes all parts), and run the tool. It writes
   `sql/locales/fr_FR/05_geo.sql`. Without regions, locations fall back to the whole sphere.
5. Run `python src/setup_db.py`. The locale then appears in `faker_list_locales` and in the application.

## Capacity and performance

Capacity:

- Names: en_US has about 390 first names per gender and 998 surnames, about 390,000 first and last name pairs per
  gender before middle names, initials, titles, suffixes and double surnames. de_DE has about 185,000 pairs per
  gender before double first names, double surnames and particles. With seed 42, 2,000 generated users have 1,998
  distinct full names and 2,000 distinct e-mail addresses in en_US, and 1,997 and 2,000 in de_DE.
- Addresses: 240 street names x 24 street types x 284 cities x building numbers up to 9999 in en_US give more than
  10^10 combinations.

Performance (MariaDB 10.4 on XAMPP, one connection, measured with `faker_benchmark_users` and
`faker_profile_primitives`):

- One user takes 11-12 ms inside the database, 85-90 users per second; a batch of 10 users takes about 0.12 s. The
  cost per user is constant, so any position is generated on demand.
- A user requires about 50-55 queries, mostly weighted picks (0.12-0.15 ms each, including the hash) and one pick
  per Markov word. A Markov sentence takes about 2 ms, a location 0.6-0.8 ms.
- With 6 parallel connections, `src/benchmark.py` reaches about 270 users per second (see the README).
- On Aiven's free single-CPU MySQL 8.4, called from a home PC, a batch of 10 users takes 0.33-0.35 s, of which about
  0.18 s is network round trip. MySQL's `ST_Contains` is about ten times faster than MariaDB's, so the border tiles
  have less effect there.
- The application caches batches by their arguments, so returning to a previous batch requires no database call.
